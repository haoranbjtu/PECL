# PECL

## Overview

This project implements PECL, a recommendation model based on graph representation learning and contrastive learning. It learns user and item embeddings from interaction data and evaluates Top-N recommendations. The current configuration uses MovieLens data.

The implementation includes a user–item interaction graph, a time-weighted graph, and a random-walk matrix, together with recommendation, contrastive, and clustering-based prototype losses. The training code in `model/graph/PECL.py` determines which loss terms are active.

## Dependencies

The main dependencies include Python, PyTorch, DGL, NumPy, pandas, SciPy, scikit-learn, PyYAML, and FAISS. The project does not provide a dependency lock file. Library versions must be compatible with the Python and CUDA environment in use.

The current PECL implementation calls `.cuda()` directly and enables GPU clustering. Full training therefore requires a suitable GPU environment; complete CPU training support is not implemented.

## Data Format

### Recommendation Data

`dataset/ml-1m/train.txt` and `dataset/ml-1m/test.txt` are text files without headers. Each row contains four fields separated by a single space:

```text
user_id item_id rating timestamp
1 1721 4 978300055
```

The loader reads the first three columns as interaction data and columns one, two, and four as temporal data. Training and test file paths are specified in the configuration file.

### Raw Data and Graph Data

`data/raw data/ml-1m/ratings.dat` contains user IDs, item IDs, ratings, and timestamps separated by `::`. Each row in `trust.txt` contains two user IDs separated by a space.

`haory_util/homo_g.py` reads these raw files, constructs graph data, and saves the output to:

```text
data/preprocessed/ml_dgl_all/homo_dataset.pkl
```

This file stores pandas data objects and DGL graph objects for use by the relevant project modules. The recommendation files `train.txt` and `test.txt` are separate inputs and are not generated by this script.

## Configuration

Configuration file: `conf/PECL.yaml`.

| Parameter | Current Value | Description |
| --- | --- | --- |
| training.set | ./dataset/ml-1m/train.txt | Training set path |
| test.set | ./dataset/ml-1m/test.txt | Test set path |
| dataset | ml | Dataset identifier |
| embedding.size | 64 | Embedding dimension |
| max.epoch | 80 | Maximum number of training epochs |
| batch.size | 2048 | Training batch size |
| learning.rate | 0.001 | Learning rate |
| reg.lambda | 0.0001 | Regularization coefficient |
| item.ranking.topN | [10, 20] | Recommendation evaluation cutoffs |
| output | ./results/ | Results directory |

The `PECL` section configures graph propagation layers, temperature parameters, loss weights, the number of clusters, and the random-walk matrix threshold. The current defaults include `n_layer: 3`, `num_clusters: 2000`, and `threshold: 0.0001`.

When changing datasets, review the data paths, fixed paths in the preprocessing script, and user and item counts in the model-related code. Changing the `dataset` field alone is insufficient.

## Module Responsibilities

- `main.py`: Checks model inputs, loads the configuration, and starts the recommender. It does not automatically convert raw data.
- `haory_util/homo_g.py`: Converts raw data, constructs and saves graph data, and creates the output directory when needed.
- `SELFRec.py`: Loads interaction and temporal data and selects the recommender specified in the configuration.
- `data/ui_graph.py`: Builds user and item indices and constructs the graphs and matrices used by the model.
- `model/graph/PECL.py`: Defines embeddings, graph propagation, training losses, and prediction logic.

## Results and Evaluation

The model calculates recommendation scores from user and item embeddings and evaluates recommendations using the configured Top-N cutoffs. Training progress and evaluation information are reported during execution. The `output` parameter specifies the results directory.

The project does not include a performance report reproduced under a standardized environment. Reported metrics should be based on actual training and evaluation runs.
